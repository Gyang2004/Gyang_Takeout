## 1. 背景与目标

### 1.1 背景

现有管理端是旧技术栈的构建产物（Vue 2 + TypeScript + Element UI），源码未入库，只有 `nginx/html/sky` 下的编译产物和 source map。项目目标是**从 0 到 1 精细化管理端前端**，因此不迁移旧代码，用新框架重写；旧产物只作为页面、交互和接口调用的参考。

后端目前只实现了员工登录/退出（`EmployeeController` 只有 `login`、`logout`），其他模块只有 DTO/VO/POJO。**本方案不做 mock，前端按后端已实现的接口分期落地。**

### 1.2 目标

1. 用 Vue 3 + Vite + Element Plus（JavaScript）重写管理端现有全部页面。
2. 统一视觉：Element Plus 主题定制 + 一套可复用的设计规范（颜色、圆角、阴影、间距、表格/表单）。
3. 只对接真实接口；后端实现一个模块，前端落地一个模块。
4. 形成清晰的工程分层，为后续逐模块迁移 TypeScript 留好边界。
5. 每个阶段都能独立验证，避免"全做完再联调"。

### 1.3 非目标

- 不改后端业务实现；接口缺口由后端排期。
- 不做用户端 / 骑手端。
- 不迁移旧代码，旧产物只作参考。
- 不引入 mock 数据层。
- 不做国际化、多角色权限（后端当前没有对应接口）。

### 1.4 当前阶段范围（p3）

- 现在只做：前端工程初始化、登录闭环、布局/路由/404，以及为未实现页面准备占位。
- 现有旧产物只作参考；前端以后端**已有接口**为准，后端实现一个模块，前端落地一个模块。
- 数据库先连本地 MySQL；后期迁云服务器通过配置切换（见 §6.4）。

### 4.3 分层职责

| 层 | 只做什么 | 不做什么 |
|---|---|---|
| `views/` | 页面编排、表单、列表展示 | 不直接写 `axios`，不写全局状态逻辑 |
| `api/` | 每个后端接口一个函数，集中路径与参数 | 不处理 UI 提示、不存状态 |
| `stores/` | 跨页面共享状态（登录态、用户信息、UI 状态） | 不直接发请求（调用 `api/`） |
| `components/` | 可复用展示组件 | 不耦合具体业务页面 |
| `utils/` | 纯函数（token、校验、格式化） | 不依赖 Vue 响应式 |
| `constants/` | 枚举、状态映射 | 不写逻辑 |

### 4.4 请求与鉴权

```js
// src/api/request.js
import axios from 'axios'
import { ElMessage } from 'element-plus'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 10000,
})

request.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) config.headers.token = token
  return config
})

request.interceptors.response.use(
  (response) => {
    const res = response.data
    if (res.code === 1) return res
    ElMessage.error(res.msg || '请求失败')
    return Promise.reject(new Error(res.msg || '请求失败'))
  },
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem('token')
      window.location.assign('/login')
    } else {
      ElMessage.error(error.message || '网络异常')
    }
    return Promise.reject(error)
  }
)

export default request
```

约定：

- 令牌存 `localStorage`，键名 `token`；请求头名与后端一致（`token`）。
- 401 统一清理登录态并跳登录页；不自动续期。
- 页面层只调用 `api/` 函数，错误提示由拦截器统一处理，业务层只处理成功分支。
- 登录成功后保存 `token`、`userName`、`name`，刷新页面从 `localStorage` 恢复。

### 4.5 路由与菜单

```js
// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  { path: '/login', component: () => import('@/views/login/index.vue'), meta: { public: true } },
  // 子路由只挂已实现页面；未实现页面不要提前加入
  { path: '/', component: () => import('@/layout/index.vue'), children: [] },
  { path: '/:pathMatch(.*)*', component: () => import('@/views/404.vue'), meta: { public: true } },
]

const router = createRouter({ history: createWebHistory(), routes })

router.beforeEach((to) => {
  const token = localStorage.getItem('token')
  if (!to.meta.public && !token) return { path: '/login', query: { redirect: to.fullPath } }
  if (to.path === '/login' && token) return '/'
})

export default router
```

菜单策略：**先由前端路由表生成菜单**，路由的 `meta.title`、`meta.icon` 作为菜单数据源。后端目前没有菜单接口，服务端驱动等后端实现后再考虑。新增页面必须同时改路由表和菜单，避免两处漂移；未实现页面挂占位组件，不接业务逻辑。

### 4.6 状态管理

- `stores/user.js`：`token`、`userName`、`name`；`login()` 调接口并持久化，`logout()` 清空。
- `stores/app.js`：侧边栏折叠、面包屑数据。
- 页面级状态留在组件内，不往 store 塞。

### 4.8 编码规范

- 组件名 PascalCase；文件与目录 kebab-case 或按旧结构统一（本方案沿用 `views/<module>/index.vue`）。
- 所有导出函数写 JSDoc（参数、返回、异常），为后续迁 TS 留接口。
- 列表页必须有：加载态、空状态、错误提示、分页参数统一（`page`、`pageSize`）。
- 表单校验用 Element Plus `rules`，不手写重复校验。
- 不写死账号密码、地址、密钥；环境差异放 `.env.*`。
- 不直接操作 DOM；需要时用模板引用。

## 5. 分期计划（按后端实现推进）

> 原则：**没有真实接口的页面不开工**。每期结束都要能演示、能回归。

### 阶段 0：工程初始化（不依赖后端）

- 产出：`frontend/` 工程、依赖安装、Vite 配置（别名、代理）、ESLint/Prettier、基础样式。
- 验收：`npm run dev` 能启动；`npm run build` 成功产出 `dist/`。

### 阶段 1：登录闭环（后端已就绪）

- 页面：登录页（账号、密码、校验、loading、错误提示）。
- 逻辑：登录 → 存 token → 跳转；路由守卫；退出；401 跳登录。
- 联调：Vite 代理 `/api` → `localhost:8080/admin`，用真实账号验证。
- 验收：错误密码有提示；刷新后登录态保持；未登录访问受保护页跳登录。

### 阶段 2：布局与导航（不依赖后端）

- 产出：侧边栏、顶部栏、面包屑、折叠、内容区、404。
- 菜单数据来自路由表；已实现页面正常挂载，未实现页面用占位页提示「功能开发中」，菜单保持可见。
- 验收：路由切换正常；占位页不报错；刷新不 404（Nginx `try_files` 验证）。

### 阶段 3：员工管理（等后端员工 CRUD）

- 前置：后端实现 `employee/page`、新增、编辑、删除、启用/禁用、修改密码。
- 产出：列表、分页、搜索、新增/编辑弹窗、状态切换、修改密码。
- 验收：每个操作都有真实接口；分页与搜索参数与后端一致。

### 阶段 4：分类 → 菜品 → 套餐（等后端对应模块）

- 顺序有依赖：分类先于菜品，菜品先于套餐。
- 每个模块完成后单独联调，不攒到最后。

### 阶段 5：订单管理（等后端订单模块）

- 前置：订单查询、接单、拒单、取消、派送、完成等接口；来单提醒若用 WebSocket 需单独确认。
- 验收：状态流转与后端一致；刷新后状态正确。

### 阶段 6：工作台与数据统计（等 report 接口）

- 前置：`report/*` 接口、导出接口；ECharts 图表。
- 验收：图表数据来自真实接口；导出文件可打开。

### 阶段 7：统一美化与切换

- 统一主题变量、间距、表格/表单样式；全页面走查。
- 构建产物接入 Nginx（`root ../frontend/dist`），验证通过后替换旧产物 `nginx/html/sky`。
- 旧产物保留一个版本周期作为回退，确认无问题后删除。

## 6. 联调与部署

### 6.1 开发环境

```js
// vite.config.js（关键片段）
server: {
  port: 5173,
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/api/, '/admin'),
    },
  },
}
```

### 6.2 构建与 Nginx

- `npm run build` 产出 `frontend/dist`。
- Nginx `location /` 改为 `root ../frontend/dist;` + `try_files $uri $uri/ /index.html;`。
- `location /api/` 保持反代到后端（见 `nginx/conf/nginx.conf:67-71`）。
- 生产构建关闭 sourcemap（`build.sourcemap: false`），不要部署 `.map` 文件。

### 6.3 环境变量

| 变量 | 开发 | 生产 | 说明 |
|---|---|---|---|
| `VITE_API_BASE_URL` | `/api` | `/api` | 同源经 Nginx 转发，避免跨域 |

### 6.4 数据库切换（本地 → 云服务器）

不需要额外写中间层代码，Spring 的分环境配置就是这一层：

- `application.yml` 只放占位符 `${sky.datasource.*}`（现有写法）。
- 本地：`application-dev.yml`（`host=localhost`，库名统一为 `sky_take_out`）。
- 云端：新增 `application-prod.yml`（填云数据库地址），启动时用 `SPRING_PROFILES_ACTIVE=prod` 或 `--spring.profiles.active=prod` 切换。
- 口令通过环境变量或启动参数注入，不写进仓库。
- 切库只改 profile / 环境变量，不改代码；MyBatis 已经屏蔽了具体 SQL 差异。
