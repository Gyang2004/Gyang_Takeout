# 接口文档（docs）

> 本目录存放**接口文档**、**Swagger / OpenAPI 文档**和**阶段性方案文档**，是「结果文档」。
> 开发过程记录不放这里，统一放 [`../notes/`](../notes/README.md)。

## 本目录放什么

- 接口说明：模块、路径、请求/响应示例、错误码、鉴权要求
- Swagger / OpenAPI：导出的规范文件（`openapi.json` / `swagger.yaml`）或在线地址记录
- 随接口配套的数据结构说明（如统一响应体、分页约定）
- 阶段性方案：如前端重构方案、接口设计说明，按 `p<序号>/` 归档

文档随开发进度补充。

## 规划结构

```
docs/
├── README.md      # 本文件：索引与维护约定
├── api/           # 接口文档，按模块拆分，如 api/user.md、api/dish.md
└── p3/            # 阶段方案文档（如 p3/前端重构方案.md）
```

## 维护约定

- **以代码为准**：接口定义以代码中的注解 / Swagger 生成为准，本目录存快照或补充说明，避免两处长期漂移；接口改动时同步更新。
- 每个接口至少写明：`method + path`、参数（类型/必填/约束）、响应结构、错误码、是否需要登录。
- 导出的 Swagger 规范文件直接入库，文件名带版本或日期，便于对比。
- 对外交付的文档（如部署说明、数据库设计）也放本目录，并在下方索引登记。
