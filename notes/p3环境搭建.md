## 3. 学习问题与简单结论

> 只给结论，细节后续补。

### 3.1 为什么生产环境常用 Nginx，而不是 Vite？

- **Vite 是构建工具 + 开发服务器**：`vite build` 产出静态文件；`vite preview` 只用于本地预览，官方不建议当生产服务器。
- **Nginx 是静态文件服务器 + 反向代理**：托管构建产物、把 `/api` 转发给后端，顺带做 gzip、缓存、HTTPS、日志。
- 两者不冲突：**Vite 负责打包，Nginx 负责线上托管和转发**。
- 我之前把前端"部署到服务器用的是 Vite"，实际也是先构建、再让某个服务把静态文件跑起来；能演示，但不适合长期生产。

### 3.2 Vite 的开发代理和 Nginx 反向代理有什么区别？

- Vite proxy：只在**开发时**生效，解决本地跨域，dev server 一关就没了。
- Nginx 反代：在**运行时/生产时**生效，前后端同源访问，跨域从架构上就不存在。
- 一句话：**开发用 Vite 代理图方便，线上用 Nginx 反代更稳、更可控。**
- 完整请求链路见 [p3_前后端请求链路](p3_前后端请求链路.md)。

### 3.3 后端为什么要用 Maven？

- **依赖管理**：用坐标声明依赖，自动处理版本和传递依赖，换机器/CI 能复现。
- **构建流程**：`clean → compile → test → package` 一条命令跑完。
- **多模块协作**：父 pom 统一版本；`sky-commons`（公共）、`sky-pojo`（实体/DTO）、`sky-server`（启动与业务）各管一摊，模块间按需依赖。
- 一句话：**统一依赖 + 统一构建 + 多模块协作。**

### 3.4 Vue 怎么配置到 Nginx 上？

1. `npm run build` 产出 `dist/`；
2. 让 Nginx 指向 `dist`：改 `root`（如 `../frontend/dist`），或把 `dist` 内容拷到 `nginx/html/sky`；
3. `nginx.conf` 的 `location / { root ...; }` 指过去；
4. `/api/` 用 `proxy_pass` 转发到后端；
5. 用 history 路由时补 `try_files $uri $uri/ /index.html;`，否则刷新页面 404；
6. `nginx -s reload` 生效。

## 8. 讨论记录（2026-11-16）

> 选型讨论中确认的问题，按「问题 → 结论」记录。

### 8.1 前端源码为什么单独放 `frontend/`？Nginx 会不会“拉取”别处代码？

- Nginx 不拉取源码，只按 `root` 读静态文件。当前 `root html/sky` 相对 `nginx/`，即 `nginx/html/sky`。
- `root` 可以指向任意目录（如 `../frontend/dist`），但不能指向源码目录：`.vue` 浏览器跑不了，也会暴露源码和依赖。
- 分离目的：`frontend/` 放源码与构建产物，`nginx/` 放 Nginx 本体与配置。

### 8.2 重写并美化 UI 后，要重新构建吗？

- 要。`nginx/html/sky` 是旧源码的构建产物，改源码不会自动更新。
- 开发用 `npm run dev`（热更新，不用构建）；联调/部署用 `npm run build` 产出 `dist/`，Nginx 指向新 `dist`。
- 旧产物在重写期间留作对照（页面、交互、接口调用），切换到新版后不再更新。
- 不要直接改 `nginx/html/sky` 里的文件，那是压缩后的产物。

### 8.3 JS 联调时要不要定义接口出入参？

- 要“知道”，但不强制检查：字段写错在运行时才暴露（`undefined`、白屏等）。
- 弥补：`api/` 集中封装 + JSDoc 注释；可选 `jsconfig.json` 开 `checkJs`；联调时用浏览器 Network 核对真实响应。
- TS 的类型也不是自动来自后端，需要手写或从 OpenAPI 生成；它保证的是“前端内部一致”，和后端一致仍要靠接口文档。

### 8.4 后续按模块迁 TS 的策略

1. **混用环境**：`tsconfig.json` 开 `allowJs: true`、`checkJs: false`；构建先保持 `vite build`，类型检查单独跑 `vue-tsc --noEmit`。
2. **迁移顺序**：先 `api/`（收益最大）→ `stores/` → `utils/`、`composables/` → 组件（自底向上）→ `views/`。
3. **收口**：全部迁完再开 `strict: true`，构建命令改为 `vue-tsc --noEmit && vite build`。
4. **JS 阶段的前置习惯**：请求集中、导出写 JSDoc、常量集中，迁移时只加类型、不改业务逻辑。

### 8.5 部署到服务器，是把 Nginx 文件拷过去吗？

- 不是拷本地的 `nginx.exe`。服务器上安装 Linux 版 Nginx，部署三样：
  1. 前端 `dist/`：上传到服务器静态目录；
  2. Nginx 配置：`root` 指向 `dist`，`/api/` 反向代理到后端，history 路由加 `try_files`；
  3. 后端 jar：`mvn package` 后运行，数据库连服务器 MySQL。
- 本地 `nginx/` 只是 Windows 下的模拟环境；配置思路一致，路径和反代地址按服务器调整。
